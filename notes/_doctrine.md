# 精读口径（从 2026-06 的 Jarvis v1 提炼，Kevin 校准过）

这是速览 prompt、deep-read skill 和前端共同遵守的"读到什么程度、怎么写"的口径。改口径先改这里。

## 目标
读完能**白板复现**：不看原文，凭记忆重搭结构、说清强在哪、藏了什么假设、在哪会崩。清晰 ≠ 深；"它有哪些层 / 做什么"是基础，没价值；要到**设计决策 + 实现机制 + 为什么这么做**。

## 论文：解释性深挖，重现作者思路，少评价
理解弧线：① 反直觉场景/悖论 → 现有方法为什么不行 → ② 最关键的概念改变；组件 → 阻断哪种失败 → ③ 最强证据（不一定是最大涨幅）；新在哪一层 → ④ 没证明什么、何时崩（小头）→ 细节与可借之处（小头）。
五句强制回答：反直觉问题 / 为何现有方法不行 / 最关键概念改变 / 哪个实验最直接支持 / 证据还不足以相信什么。
承重机制直觉按类型给：数学 / 系统 / 算法 / 数据 / eval。
篇幅：问题 + 方法 + 结果占大头；局限、迁移是小头。

## 项目：成熟度判断 + 横向对比才是价值
先分类型（skill / 教学 / 工具 / 架构型）定深度。① 为什么存在 → ② 为什么现在上榜（查 release / CHANGELOG）→ ③ 怎么搭（回真源码；机制级：检测条件 → 处理动作；agent = 循环 + 中间件）→ ④ 失败模式配正向机制 → ⑤ 成熟度 + vs 同类 → ⑥ 哪种创新。
优势 / 实现为主，风险 ≤ 15%。不写"用到你项目/简历"的硬套迁移段。

## 选稿
热度 = 注意力信号，不是质量信号。项目必须来自 GitHub Trending（日/周/月榜），不允许 noise。当天没好料可以少甚至空，不硬凑。

## 写法
术语首现一句硬定义；类比讲解决机制而非复述问题；自创分层标"解读层"；不做时间/因果反推；四级信息标注（原文声称 / 文献结论 / 合理推断 / 不确定猜测）；先判断后证据；少形容词；不空泛夸赞；保留不确定；中文，术语 / 数字 / 专名保留原文。

## 前端
利用好屏幕宽度：右侧不留白，放辅助理解的东西（示意图、前置概念、关联）；增加读下去的欲望。
